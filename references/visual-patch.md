# 视觉补丁（ADR-008 降级路径）

课件分两种：文字型（文本层够用）和**图密集型**（每页就几个字，信息全在图里 —— 时序图、状态机、
对比表、公式）。第二种光靠 `text` 出来的正文写不出像样的总结，需要**按需看几页图**，这就叫视觉补丁。

## 什么时候需要

`extract` 之后看 stats：

- `chars_after / kept_pages < ~200` 字符/页 → 大概率是图密集型
- 或者你看 `text` 的输出，发现关键内容（握手时序、状态迁移、公式）只有标题、没有过程

M5 的实例：网络编程 03-transport，39 页只有 6,856 字符（≈176 字符/页），
三次握手、状态机、TIME_WAIT 全在图里 → 做了 8 页视觉补丁。

## 怎么做

**准备渲染工具**（一次，macOS；需要 `swiftc`，Xcode Command Line Tools 自带）：

```bash
cd <skill 仓库根>
swiftc -O tools/pdfrender.swift -o /tmp/pdfrender
```

**渲染关键页**（一次一页；输出目录必须在 agent 能读图的范围内）：

```bash
/tmp/pdfrender ~/.course-digest/docs/<docId>/source.pdf /tmp/pages 7 2.0    # 第 7 页，2 倍缩放
for p in 7 17 22 25 28 31 36 38; do /tmp/pdfrender "<原始 PDF>" /tmp/pages $p 2.0; done
```

**看**：把这几张 PNG 一起交给模型（OpenClaw 是 `view_image`，其它 harness 用各自的读图能力）。

**挑哪几页**（按性价比排序）：

1. 对比表 / 汇总表（一页顶十页）
2. 时序图（握手、挥手、重传）
3. 状态机图与状态迁移
4. 公式页
5. 结构图（分层模型、框图）

不要整本渲染 —— 那是把 PDF 塞进上下文，等于放弃了压缩的意义。

## 写回总结

- 把图上的信息写进**对应锚点**的段落里（图在哪页，锚点就指哪页）
- 图里的细节如果模型看不真切，就**别写死数值**；真要写，在总结里标注
  「此式/此数据由视觉识别，建议核对原文」（ADR-008）
- 总结末尾注明哪几页做过视觉补丁，让看的人知道边界在哪

M5 那次的末尾说明：

> 课件 39 页，文本层只提取到 6,614 字符（正文极薄），因此对图密集的页面
> （P7 对比表、P17 UDP 头部、P22/P28 握手时序与状态、P25 状态机、P31/P36 释放时序、
> P38 TIME_WAIT）做了视觉补丁，其余按文本层整理。

## 边界

- 没有 `swiftc` / 不是 macOS → **做不了**这一步。那就按文本层写，并在交付时**如实说明**
  "未做视觉补丁、图里内容未纳入" —— 不要假装看过图
- 视觉补丁是**按需**的：文本层够用的课件别做，纯属浪费
